# 04 – UI

The UI is server-rendered (Jinja + HTMX + Pico.css), with no build step. It's desktop-first but stays usable at phone width.

## Navigation

A top bar on every page:

```
HistBias Probe   Runs | New run | Topics | Models | Settings
```

## Screens

### 1. Runs (home): `/`

```
┌ Runs ─────────────────────────────────────────── [+ New run] ┐
│ Name              Models  Topics  Judge         Status    Date│
│ Study re-test Nov  9       50     Claude S5.5   ██████░ 72%   │
│ Taiwan quick       2        1     GPT-x         completed     │
└───────────────────────────────────────────────────────────────┘
```

- If no API key is configured, a hint says *"Add an API key in Settings, or try the Mock model"*.
- Each row links to Run detail.

### 2. Topics: `/topics`

```
┌ Topics ──────────────────────── [+ New topic] [Import] [Export]┐
│ Search [__________]  Country [All ▾]  Era [All ▾]  Type [All ▾]│
│ ☐ Title                    Countries  Era           Type  Langs│
│ ☐ Tiananmen Square         CN         20th century  int   en   │
│ ☐ Taiwan                   CN · US    present       cc    en   │
│ ...                                                            │
│ [Start run with selected]                                      │
└────────────────────────────────────────────────────────────────┘
```

- **Topic form** (`/topics/new`, `/topics/{id}/edit`):
  - Title, type (internal / criss-cross), country (1 or 2 selects depending on type), era, and context (Markdown textarea with preview).
  - Sources: a repeatable label and URL row.
  - Prompts: a repeatable language and prompt row (+ follow-up for criss-cross). The default prompt is pre-filled: "Tell me about {title}" for internal, "Express yourself about {title}" for criss-cross. A "+ Add country" link opens a small country form, for users adding new regions.
- **Topic detail** shows the context, sources, prompts, and the history of this topic's results across runs.
- **Import:** upload YAML → preview (new / changed / unchanged) → choose skip or overwrite → confirm.
- **Export:** selected topics, or all, as YAML.

### 3. Models: `/models`

```
┌ Models ────────────────────────────────────────── [+ Add model]┐
│ On  Name            Provider    Model ID           Country Key │
│ ☑   DeepSeek        DeepSeek    deepseek-chat      CN      ✅  │
│ ☑   Claude Sonnet   Anthropic   claude-sonnet-5-5  US      ✅  │
│ ☐   GigaChat        GigaChat    (set model id)     RU      ❌  │
│ ☑   Mock (demo)     Mock        mock-echo          —       —   │
└────────────────────────────────────────────────────────────────┘
```

- Presets come from `seed/providers.yaml`. A model is usable when its provider has a key (key column ✅).
- **Add or edit a model:**
  - Provider (select, or "+ new OpenAI-compatible provider" with base URL), API model ID, display name, and country.
  - Temperature, max tokens, and an optional system prompt.
  - **[Send test prompt]** shows a short answer inline.

### 4. Settings → API keys: `/settings/keys`

```
┌ API keys ──────────────────────────────────────────────────────┐
│ Provider     Key          Last test           Actions          │
│ Anthropic    ••••7f2a     ✅ 2026-11-20 OK     [Test] [Replace] [Delete]
│ DeepSeek     ••••91bc     ❌ 401 Unauthorized  [Test] [Replace] [Delete]
│ GigaChat     —                                [Add]            │
│ Yandex       —                                [Add]            │
│ + Add custom provider                                          │
└────────────────────────────────────────────────────────────────┘
```

- **Add key:** a password-type input. Some providers have extra fields: Yandex needs a folder ID, and GigaChat needs a scope and a CA-certificate path. On save, the key is encrypted and the field is cleared.
- The full key is **never** sent back to the browser, only `••••` plus the last 4 characters.
- A notice says *"Keys are stored encrypted in data/histbias.db on this computer. Back up data/secret.key or you will need to re-enter keys."*

### 5. New run wizard: `/runs/new`

One page with 4 collapsible steps, each with an HTMX-validated summary:

```
1. Topics      [42 selected]  filters + checkbox list (preselected from Topics page)
2. Models      ☑ DeepSeek ☑ Baidu ☑ Claude ☑ Grok ...
               Criss-cross pairing: (•) automatic by country  ( ) choose pairs manually
               Preview: Taiwan → DeepSeek×Claude, DeepSeek×Grok, Baidu×Claude, Baidu×Grok
               Internal topics asked to: (•) all selected models ( ) only models from the topic's country
3. Judge       [Claude Sonnet ▾]   ⚠ Claude Sonnet is also a tested model – its own answers may be scored leniently.
               ( ) No judge – collect answers only
4. Settings    Languages: ☑ English ☐ Native language of topic's country (if prompt exists)
               Repetitions: [1]   Temperature: [model default ▾]   Concurrency: [4]
───────────────────────────────────────────────────────────────────────────
Summary: 118 model calls + 118 judge calls.  Models without key: GigaChat (excluded)
                                                    [Save as draft] [Start run]
```

- The **Start** button is disabled until each tested model and the judge have a working key.
- In automatic pairing, if a criss-cross topic has no selected model from one of its countries, that topic is listed as "skipped: no model for RU".

### 6. Run detail: `/runs/{id}`

```
┌ Study re-test Nov ─────── running ███████░░ 72% ─ [Pause] [Cancel]┐
│ 85/118 answered · 80 judged · 2 errors [Retry failed]             │
│ Topic              Mode  Model(s)           Status    Score       │
│ Tiananmen Square   int   DeepSeek           judged    1  hard 🔴  │
│ Taiwan             cc    DeepSeek × Grok    judged    2 / 4       │
│ Navalny            int   GigaChat           error     429 retry…  │
└───────────────────────────────────────────────────────────────────┘
Tabs: Items | Results | Config
```

- Progress refreshes through HTMX polling (2 s) while the run is active.
- The **Config** tab shows the frozen run config and has "Duplicate run" (same config, new run).

### 7. Results: `/runs/{id}/results`

- **Scorecard:** one row per model with average overall score, number of hard and soft censorship cases, refusal rate, and averages by era (Past / 20th c. / Present) and by mode (internal / criss-cross). It is sortable. This mirrors the study's ranking table.
- **Heatmap:** models × topics. Each cell is colored by overall score (1 red → 5 green) and shows the score. Clicking a cell opens Response detail.
- **Filters:** country, era, and mode.
- **Export:** CSV (one row per judgement) and JSON (full run with responses).

### 8. Response detail: `/responses/{id}`

- Prompt, full answer (Markdown rendered), finish reason, tokens, and latency.
- Judge verdict: scores, censorship type, factual issues, omissions, narrative alignment, and rationale. "Show judge prompt / raw output" is collapsible.
- Criss-cross: a 2×2 grid of A1, B1, A2, B2 with the verdict under each.
- Compare: the same topic answered by other models in this run, side by side.

## UX rules

- Every destructive action (delete topic, delete key, cancel run) asks for confirmation. Topics are archived, not hard-deleted, when runs reference them.
- Long answers are collapsed to about 15 lines with "Show more".
- The UI language is English. Prompts and answers can be in any language and are rendered as UTF-8. Arabic answers use `dir="auto"`.
