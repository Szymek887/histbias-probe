# CLAUDE.md – guidance for implementation sessions

## What this is
HistBias Probe: a local web app that runs a bank of historical and political questions against chosen LLMs and scores the answers for censorship and bias with a judge model. It comes from the AGH study "Ocenzurowanie i polityka historyczna w wypowiedziach LLM" (Q4 2026). Read `README.md`, then the docs in `docs/` in numeric order. They are the spec.

## Conventions
- Python 3.12, `uv`, FastAPI, SQLModel, Alembic, Jinja2 + HTMX, Pico.css. No JS build step; vendor static libs into `app/web/static/`.
- Async I/O for all provider calls (`httpx.AsyncClient`).
- Business logic goes in `app/services/` and `app/engine/`. Routes stay thin.
- Every schema change gets an Alembic migration.
- Tests: `uv run pytest`. Use the `mock` provider and `respx`. Never call real APIs in tests.

## Hard rules
- Never log, render, store in plain text, or export API tokens. See `docs/07-security.md`.
- Render model output only through the sanitizing Markdown renderer. Never mark it `|safe`.
- Runs must keep their snapshot (prompt, model ID, config). Don't rewrite past results when topics or models change.
- Keep the default bind at `127.0.0.1`.
- `seed/topics.yaml` is generated by `scripts/extract_wiki_seed.py` from the study wiki. Fix data in the wiki or in the script, or document manual edits.
